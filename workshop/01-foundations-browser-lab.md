# Foundations browser lab

## Goal

Move one focused documentation change through branch, commit, pull request, and review.

Fork this repository with your organization-approved GitHub account, where policy permits, and do this exercise in your fork. Do not open pull requests against the public reference repository.

## Before you start

1. Fork the repository.
2. In your fork, open the **Actions** tab and enable workflows so the `test` check runs.

## Change

Add this sentence under the workshop change request in `docs/requirements.md`:

> Reviewers should confirm the due-date boundary behavior before accepting the change.

## Flow

1. Create a uniquely named branch in your fork.
2. Make only the requested change.
3. Commit with an intent-focused message.
4. Open a pull request. Set the **base repository** to your fork, not the upstream reference repository. Explain the problem and evidence.
5. Ask a partner to review the exact requirement change.
6. Confirm the `test` check passes.
7. Merge in your fork only if your facilitator or team practice allows it.
